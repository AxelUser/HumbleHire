# ADR-009: TypeScript types for the wire format are generated from the schema

- **Status**: Accepted
- **Date**: 2026-06-04
- **Feature**: serialization

---

`document.ts` is generated by `json-schema-to-typescript` from the JSON schema as part of the `gen:schema` script. It is not a hand-written interface. The schema is the single source of truth for the wire format shape and the TypeScript types.

## Why not a hand-written interface

`document.ts` was previously a hand-written `CvDocument` interface. As the schema grows, the type and schema can drift silently: a new extension field added to the schema but not the type, or the reverse. Generating the type from the schema prevents that drift. Field descriptions written in the schema also surface as JSDoc on the generated interfaces.

Note: ajv's TypeScript support (`JSONSchemaType<T>`) runs in the opposite direction. It type-checks a schema against an existing type and does not generate types from a schema. `json-schema-to-typescript` is the correct tool for schema-to-type generation.

## Version bump contract

A schema bump is required for any of:

- Adding, removing, or changing a HumbleHire extension field
- A deliberate re-sync of the inlined JSON Resume base with a newer upstream release

The `@jsonresume/schema` interop test (see [ADR-008](./ADR-008-self-contained-schema.md)) is the signal for the second case. The version number has one source of truth: the schema `$id` and filename. `SCHEMA_VERSION` in `parse.ts` and the literal written into `meta.humblehire.schemaVersion` in `serialize.ts` are kept in sync by test.
