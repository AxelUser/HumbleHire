# ADR-007: Render the editor preview with PDF.js, not an iframe

- **Status**: Accepted
- **Date**: 2026-05-20
- **Feature**: export

---

The editor's live preview renders the exported PDF onto a canvas with PDF.js, with the text layer enabled. It does not point an `<iframe>` at a blob URL. This is split from [ADR-002](./ADR-002-client-side-pdf-generation.md), which covers why the PDF is built in the browser at all; this ADR covers only how that PDF is shown in the preview pane.

## Why not the iframe

Passing the PDF bytes to `URL.createObjectURL()` and pointing an `<iframe>` at the result is simpler and needs no extra dependency, but it fails on iOS. Every browser on iOS runs inside WKWebView, which does not render PDFs inline in an iframe: the frame either blanks or the browser forces a download. HumbleHire targets mobile as a first-class platform, so the preview has to work there.

PDF.js decodes the bytes and paints each page onto a `<canvas>`, which is consistent across mobile browsers. Its text layer keeps the preview text selectable, matching the feel of a native PDF viewer.

## Consequences

- The preview is byte-accurate to the downloaded file, because both come from the same generated bytes.
- PDF.js (~900 KB plus a ~1.2 MB worker) is lazy-loaded only when the preview pane opens. The dashboard export path never loads it.
